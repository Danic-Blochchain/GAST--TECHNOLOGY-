HOW A TRANSACTION SELF-VALIDATES — STEP BY STEP
1
SENDER BUILDS THE GAST PACKAGE
The sender constructs a transaction package locally — no mining pool, no mempool queue. It includes the amount, receiver, their current H1 hash, UTXO keys, and a proposed H3 state lock.
→ Signs it with CRYSTALS-Dilithium3 post-quantum key before sending.
2
NODE CHECKS H1 — LINEAGE LOCK (L1)
The receiving node checks that the transaction's previous H1 matches its own database record for that sender. This proves the transaction is built on the correct history — not a replay or fork.
→ If H1 mismatches, the transaction is rejected instantly. No consensus needed.
3
NODE CHECKS H2 — UTXO VIABILITY (L2)
The node verifies the referenced UTXO keys exist and that the total input value covers the amount plus the 1% platform fee. This confirms the sender actually has the funds they claim.
→ No global balance lookup — every node holds the full account state locally.
4
NODE CHECKS H3 — STATE INTEGRITY LOCK (L3)
The node independently recalculates the expected H3 hash using the sender's current state. If the proposed H3 in the package matches — the transaction is proven untampered and safe to commit.
→ This is the double-spend killer. Any manipulation breaks H3 immediately.
5
STATE QUEUED → VBLOCK ATOMIC COMMIT (H4)
Validated state is queued in a buffer. Every 20 seconds — or when 3,000 accounts are buffered — a VBlock is generated and committed atomically to LevelDB. Old UTXOs are deleted and replaced with the new H2 snapshot, preventing state bloat permanently.
→ H4 seals the VBlock and chains it to the previous one. Any tampering breaks the full chain.
⚡
NO GLOBAL CONSENSUS
Each account validates itself using its own H1 lineage. No voting. No leader. No waiting for other nodes to agree.
🔒
SELF-CONTAINED PROOF
Every GAST package carries everything needed to verify it — H1, H2 snapshot, H3 lock, and PQ signature. The node needs no external information.
🌐
INSTANT GOSSIP
Once validated locally, the package is gossiped to peers via ZMQ. Each peer re-validates independently — no single point of trust.
